# Frigate: особенности API и MQTT

## JWT: без `role` токен отвергается

Frigate требует в токене `sub`, `role` и `exp` и отклоняет его, если чего-то нет. Токен без `role` не примут, каким бы верным ни был секрет — 401 в этом случае не про секрет. Отсюда `FRIGATE_AUTH_ROLE` в конфиге. Метки времени — целые секунды, как определено в JWT.

## Адрес NVR нельзя нормализовать через `new URL()`

`FRIGATE_URL` может нести префикс пути (реверс-прокси перед Frigate), а `origin` его отбросит. Поэтому нормализация написана вручную. Порт при этом существенен: класс символов, не включавший `:`, оставлял `http://frigate:5000/` со слэшем, и все запросы уходили на `//api/...`.

## MQTT в конфиге NVR по умолчанию выключен

Frigate публикует события только если секция `mqtt` включена, а его минимальный конфиг идёт с `enabled: false`. При выключенном MQTT снаружи NVR выглядит полностью здоровым — UI работает, API отвечает, снимки и `frigate/available` по-прежнему лежат на брокере — но ни одного события не публикуется. От сломанного адаптера это неотличимо, пока кто-нибудь не прочитает конфиг; этим и занимается `checkMqttConfig`.

## Экспорт таймлапсов

`exportFile` отдаёт nginx самого Frigate, а не API, поэтому он принимает голое имя файла, а не внутренний путь контейнера из записи об экспорте.

Frigate поддерживает ровно два коэффициента ускорения на API экспорта — таблица в коде обязана совпадать с его собственной.

## Ручные события

Frigate умеет создавать событие по запросу и пишет для него настоящую запись — на этом строится e2e-проверка медиаконвейера. Но о ручных событиях он **не** объявляет в `frigate/events`, поэтому канонический `SpotterEvent` публикует вызывающая сторона.

## `frigate/events` и `frigate/reviews` не упорядочены между собой

Это независимые топики, и вердикт (`alert`/`detection`) обычно приходит чуть **позже** события `new`, которое он покрывает. Поэтому `ReviewVerdicts` обрабатывает оба направления: уже пришедший вердикт штампует событие на выходе, а пришедший позже применяется к следующему `update`/`end` — этого достаточно, поскольку значимое уведомление отправляется на `end`.

## Ручное событие с длительностью нельзя закрыть вручную

Frigate закрывает его сам и отвечает отказом: «has a set duration and can not be ended manually», оставляя ошибку в своём логе на каждом прогоне теста.

## Подписка на топики — по одному, не пачкой

Брокер, отклонивший одну подписку (ACL, неизвестный его версии топик), заваливает весь батч. Необязательный топик утянул бы за собой существенные, поэтому каждая подписка оформляется отдельно, а отказ логируется и пропускается.

## Имя коэффициента ускорения — не обещание

Фактическая скорость `timelapse_25x` определяется тем, что записано в `record.export.timelapse_args` конфига Frigate.

## Готовый экспорт отдаёт nginx

Файл лежит в `/exports/` за той же авторизацией, что и API. Поле `video_path` указывает внутрь контейнера и снаружи недостижимо.

## Снятие suspend отдельного топика не имеет

Frigate принимает счётчик минут на `frigate/<камера>/notifications/suspend`. Снять приостановку выделенным топиком нельзя — очищается повторной публикацией `ON` в `notifications/set`.
