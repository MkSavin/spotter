# Развёртывание Spotter

**Поставил → ответил на вопросы мастера → работает.** Всё остальное мастер сделает сам.

Не знаешь, какую топологию выбрать — бери **single**. Одна машина, ничего настраивать не надо.

---

## Что нужно на машине

**Docker** с Docker Compose и **bun**:

```bash
# Docker: https://docs.docker.com/engine/install/
# bun:
curl -fsSL https://bun.sh/install | bash
```

Дальше:

```bash
git clone https://github.com/mksavin/spotter.git spotter
cd spotter
```

Приготовь заранее:

- доступы к **S3** (любой S3-совместимый: MinIO, Selectel, Backblaze…)
- **токен Telegram-бота** от [@BotFather](https://t.me/BotFather)
- адрес и пароль твоего **NVR/Frigate**
- ответ на вопрос: **есть ли у тебя MQTT-брокер?** (см. ниже)

## Про MQTT — это важно

События приходят не из API Frigate, а через **MQTT**: Frigate сообщает о движении в брокер, Spotter читает оттуда. Без этой связи бот будет молчать, хотя все контейнеры зелёные.

Мастер спросит, поставить свой брокер или использовать готовый.

**Свой брокер** (по умолчанию). Тогда Frigate должен до него достучаться:

- **Frigate в Docker** — подключи его к нашей сети. В его `docker-compose.yml`:

  ```yaml
  services:
    frigate:
      networks: [spotter-mqtt]
  networks:
    spotter-mqtt:
      external: true
  ```

  Порт при этом не открывается наружу вообще.

- **Frigate не в Docker** — мастер откроет порт на этой машине и подскажет адрес.

**Готовый брокер.** Если у тебя уже есть MQTT (часто идёт вместе с Home Assistant) — укажи его, свой мы не поднимем.

Если он в Docker, мастер спросит имя контейнера и **имя его сети** (`docker network ls`) — мы подключим к ней `spotter-frigate`, и брокер будет виден по имени. Без этого адаптер упадёт с `getaddrinfo ESERVFAIL`: имя чужого контейнера не резолвится из нашей сети.

Если брокер не в Docker, а просто на этой машине — адрес `172.17.0.1`, а не `127.0.0.1`: внутри контейнера loopback означает сам контейнер.

В обоих случаях в `config.yml` самого Frigate нужна секция:

```yaml
mqtt:
  enabled: true
  host: mosquitto        # или IP машины, если Frigate не в Docker
  port: 1883
  topic_prefix: frigate
```

Проверить, что события доходят: `./spotter doctor` — там есть строка «События от Frigate».

## Вариант 1. Одна машина (`single`)

Самый простой: и камеры, и Telegram на одной машине.

```bash
./spotter install single
```

Мастер спросит S3, токен бота и доступ к камерам, поднимет всё и напечатает код доступа. Отправь его боту:

```
/login <код>
```

Готово.

---

## Вариант 2. Две машины (`cloud` + `ingest`)

Нужен, когда интернет рядом с камерами слабый или нестабильный. Тогда события копятся на месте и досылаются, когда связь появится.

- **cloud** — VPS: бот, база, веб
- **ingest** — машина рядом с камерами: запись и перекодирование

### Сначала cloud

```bash
./spotter install cloud
./spotter token
```

### Потом ingest

```bash
sudo ./spotter install ingest
```

`sudo` нужен, чтобы мастер настроил защищённый канал до cloud — он делает это сам. Один раз попросит вставить строку на cloud-машине и подскажет, куда.

Подробнее про канал: [tunnel.md](tunnel.md).

## Команды

| Что | Команда |
| --- | --- |
| Поднять | `./spotter up` |
| Остановить | `./spotter down` |
| Статус | `./spotter ps` |
| Только один сервис | добавь его имя: `./spotter down frigate`, `./spotter up frigate` |
| Логи | `./spotter logs server` |
| Код доступа | `./spotter token [viewer\|user\|admin]` |
| Обновить до свежих образов | `./spotter update` |
| Перезапустить | `./spotter restart [сервис]` |
| Самодиагностика | `./spotter doctor` |
| Настроить канал до cloud | `sudo ./spotter tunnel` |

Три похожие команды различаются так: `restart` перезапускает на том же образе, `recreate` пересоздаёт контейнеры (нужно после правки портов и адресов в `.env`), `update` скачивает свежие образы и пересоздаёт.

Полный список — `./spotter help`.

На Windows пиши `spotter` без `./`.

## Полезные флаги

Добавляются к `install` и `up`:

| Флаг | Что делает |
| --- | --- |
| `--pwa` | поднять веб-приложение с уведомлениями |
| `--email` | поднять рассылку на почту |
| `--no-gpu` | не использовать видеокарту (ingest) |
| `--no-watchtower` | не обновляться автоматически |

Например:

```bash
./spotter install cloud --pwa
```

PWA нужно ставить за HTTPS — иначе уведомления в браузере не работают.

Как часто проверять обновления — отдельной командой: `./spotter watchtower 3600` (см. [operations.md](operations.md)).

## Что-то пошло не так

Сначала — самодиагностика. Она проходит по цепочке и называет сломанное звено:

```bash
./spotter doctor
```

Проверяет контейнеры, Redis, доступность Frigate, каталог камер, S3, Telegram API и канал до облака (на ingest). Для каждой проблемы печатает подсказку.

Дальше — логи:

```bash
./spotter ps        # что поднялось
./spotter logs      # что пишут сервисы
```

Частые случаи:

| Симптом | Причина |
| --- | --- |
| `bun: command not found` | не поставлен bun (см. выше) |
| `в .env нет SPOTTER_MODE` | не запускал `install` в этой папке |
| Бот молчит | неверный `TELEGRAM_TOKEN` или недоступен `api.telegram.org` |
| «Список камер пока недоступен» | адаптер не достучался до Frigate — `./spotter doctor` на ingest |
| `client version 1.25 is too old` | старый образ watchtower — `git pull` и `./spotter update` |
| Нет видео в сообщениях | не заполнены `S3_*` или бакет недоступен |
| `port is already allocated` (1883) | у тебя уже есть свой MQTT — выбери «готовый брокер» |
| `getaddrinfo ESERVFAIL` | адаптер не видит брокер по имени — укажи `MQTT_NETWORK` (сеть брокера) |
| События не приходят, всё зелёное | Frigate не публикует в тот брокер — проверь `mqtt` в его `config.yml` |
