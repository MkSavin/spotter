# Проверка готовности

Перед кодом сверься с [инвариантами](invariants.md) и соответствующими находками в `docs/foundings`.

1. Добавь тест, который падает без исправления; для регрессии проверь его откатом правки.
2. На стыке с внешней системой используй настоящий компонент: Docker, Redis, S3, ffmpeg, Telegram, Appercot или NVR. При изменении образа собери его через Dockerfile с filtered install.
3. Прогони `bun run green`: TypeScript, тесты, бюджет документации и Biome. Тот же gate стоит в pre-commit.
4. Для полного пути используй `bun run test:e2e`; для образов и compose — `bun run smoke:build`, затем `bun run test:smoke`.
5. Проверь diff через `/code-review` перед коммитом. Одна проблема — один коммит; рискованное исправление начинается с падающего сквозного теста.
6. Непроверенное поведение называй непроверенным. Утверждение о проде без логов — гипотеза.

Документация меняется вместе с кодом. `AGENTS.md` ограничен 3072 байтами, каждый `.agents/**/*.md` — 8192 байтами; размер считается после нормализации CRLF. Проверка находится в `.integration/docs.test.ts` и входит в общий тестовый gate.

Известные незакрытые проверки перечислены в [todo](todo.md); закрытый пункт удаляется.
