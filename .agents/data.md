# Данные

Каждый сервис владеет отдельным SQLite-файлом. Схема находится в `src/db/schema.ts`, открытие и миграции — в `client.ts`, доступ — в `repository.ts`. Бизнес-логика не вызывает Drizzle напрямую. `bun:sqlite` синхронный, поэтому repository возвращает значения, не промисы.

| Сервис | Локальные данные |
| --- | --- |
| server | `recipients` с UUID, ролью и platform-specific identity; одноразовые `access_tokens`; доменные `events` без message-id |
| telegram | чаты, привязки recipient/chat, message-id событий и частей клипов, версии сервисов, ожидания таймлапсов |
| pwa | push-подписки, авторизованные устройства, дедуп, лента и запущенные таймлапсы |
| email | дедуп-леджер писем |
| appercot | чаты и роли, события и message-id, медиазапросы и отложенные результаты, идемпотентность входящих команд, каталог |

Чужой домен изменяется только через `command.request`. Роль в локальной БД фронтенда — кэш; истина находится в server.

После правки схемы выполни `bunx drizzle-kit generate` в каталоге сервиса. Каталог `drizzle/` должен попасть рядом с приложением в образе. Миграции применяются при старте.

`DATABASE_PATH` по умолчанию равен `./data/<service>.sqlite` относительно cwd. Этот дефолт остаётся в коде и не выносится в общий `.env`.

Retention удаляет устаревшие события, коды, связи сообщений и запросы по правилам конкретного сервиса. Удаление события Appercot каскадно удаляет его message-id; очистка чата забывает только локальные связи сообщений.
