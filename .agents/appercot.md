# Appercot

`apps/appercot` — опциональный фронтенд на `@appercot/chat` и `@appercot/protocol`. Он подключается к Appercot по WebSocket, читает общие Redis-потоки Spotter и использует SQLite для локального состояния. Пользовательский запуск — в [docs/appercot.md](../docs/appercot.md).

## Вход и роли

`/start <код>` и `/login <код>` вызывают доменный `appercot.redeem`. Server связывает стабильный Appercot `userId` с recipient UUID; именной код Appercot нельзя погасить в Telegram и наоборот. Локальная роль — кэш доменной.

После входа, выхода и `spotter.delivery.recipient` сервис синхронизирует одну роль Appercot: `spotter_viewer`, `spotter_user` или `spotter_admin`. Платформенная роль `owner` не заменяет доменную авторизацию: владелец может видеть ограниченные пункты меню, но router отклонит их без роли Spotter. Logout и revoke прекращают доставку; повторный update не авторизует самовольно вышедший чат.

Входящие message/command/callback дедуплицируются по ID. Результат сохраняется до отправки: повтор после сетевого сбоя не гасит код и не запускает команду дважды. Обработка сериализуется per chat; `ackOnError: false` оставляет неуспешное событие Appercot для повторной доставки.

## События и медиа

Событие сохраняется перед fan-out, а `(eventId, chatId)` связывается с исходным message-id. Повторное create редактирует сообщение вместо дубля. Снимок загружается из S3 в Appercot и переиспользуется по `fileId`; при ошибке загрузки кнопка выдаёт подписанную ссылку.

Кнопка клипа вызывает `event.clip`. Прогресс обновляет исходное сообщение; готовый `clipKey` и повторное нажатие выдают свежую ссылку. Таймлапс и кадр камеры создают отдельное сообщение запроса. Их `requestId` проходит через Redis-контракты и возвращает результат только инициатору с действующей ролью.

Блокировка бота сохраняется и исключает чат из доставки. Результат запроса, пришедший во время блокировки, сохраняется отдельно от его показа и дорисовывается после unblock. Mute хранится в SQLite и действует после рестарта. Retention удаляет старые события, запросы и входящие взаимодействия.

Upload снимка прерывается только при отсутствии новых чанков в течение 30 секунд; активная передача не имеет общего лимита длительности. При ошибке остаётся подписанная ссылка.

## Запуск и проверка

Обязательны `APPERCOT_TOKEN`, `APPERCOT_WS_URL`, Redis и S3. `APPERCOT_S3_PUBLIC_URL` задаёт внешний endpoint для ссылок, если `S3_HOST` доступен только внутри сети. Compose-профиль — `appercot`, группа Redis — `spotter-appercot`, БД — `./data/appercot.sqlite`.

`bun test` в `apps/appercot` проверяет повторный вход, дедуп события и upload, кадр, таймлапс, клип, block/unblock и синхронизацию ролей. Настоящий Appercot используется для приёмки WebSocket, сообщений, ролей и upload; автоматический стенд пока перечислен в [todo](todo.md).
